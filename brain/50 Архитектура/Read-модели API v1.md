# Read-модели API v1

> Быстрые производные представления не владеют фактами и всегда могут быть
> пересобраны из нормализованных таблиц PostgreSQL.

## Проекции

| Таблица | Назначение | Первичные факты |
|---|---|---|
| `student_dashboard_view` | ближайшие занятия и состояние ученика | enrollment, lesson, assignment, attempt |
| `tutor_today_view` | расписание и загрузка репетитора | lesson, group, members |
| `assignment_progress_view` | прогресс каждого ученика по заданию | assignment, tasks, attempt |
| `student_subject_stats` | решено, верно, активное время по предмету | task, attempt |

Statement-level PostgreSQL triggers вызывают `rebuild_read_models()` после
изменения дешёвого набора учебных фактов. Для текущей нагрузки до 200
пользователей синхронность проще и надёжнее отдельного worker. При измеренном
росте стоимости rebuild механизм заменяется инкрементальным outbox consumer без
изменения публичного API.

Команда `npm run db:read-models:rebuild` пересобирает все четыре таблицы и
сверяет их с независимыми запросами к первичным фактам. Расхождение делает
команду неуспешной.

## Инварианты

- источник истины — нормализованные таблицы, не проекции;
- API повторно проверяет роль и владение до чтения проекции;
- эталонного `Task.answer` нет ни в одной публичной read-модели;
- rebuild безопасен после восстановления backup или изменения алгоритма.
