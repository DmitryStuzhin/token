# Production-развёртывание

> Первый production-контур Token создаётся в Timeweb Cloud для старта до 200 пользователей.

## Создано

- VPS `token-prod-1`, Ubuntu 24.04, Москва: 2 vCPU, 4 ГБ RAM, 50 ГБ NVMe;
- вход `root` по выделенному ED25519 SSH-ключу, парольный SSH отключён;
- один провайдерский backup сервера;
- назначены публичные IPv4 `201.24.125.152` и IPv6 `2a03:6f00:a::1:e4b7`;
- создан непривилегированный пользователь `deploy` с доступом по ED25519;
- установлен Docker 29.1.3 и Docker Compose 2.40.3;
- включён UFW: вход разрешён только на TCP 22, 80 и 443;
- зарегистрирован домен `tokenapp.ru`, оплачен до 2027-08-09.
- production-контур описан в `Dockerfile`, `infra/compose/production.yml` и
  `infra/compose/Caddyfile`; наружу публикуются только Caddy 80/443.
- PostgreSQL 16.4 и приложение развёрнуты 2026-08-09; оба контейнера healthy,
  `/health/ready` возвращает `200`, production-база создана и пока пуста;
- Caddy временно остановлен до публичной DNS-делегации, чтобы не расходовать
  лимиты ACME; после появления A-записи он выпускает TLS автоматически.

## Целевой состав первого контура

- reverse proxy с TLS;
- один процесс приложения Token;
- PostgreSQL и Redis в изолированной Docker-сети;
- закрытые постоянные volumes;
- приватный S3 для пользовательских файлов и контента ЕГЭ;
- отдельное off-site хранение резервных копий PostgreSQL.

## Блокеры публикации

1. Публичная DNS-делегация `tokenapp.ru` ещё распространяется; до появления
   A-записи `201.24.125.152` нельзя выпустить TLS-сертификат.
2. [[Безопасность|Production Identity и безопасность]] ещё не завершена полностью;
   публичный запуск допускается только после минимального security-gate.
