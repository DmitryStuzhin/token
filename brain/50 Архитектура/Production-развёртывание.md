# Production-развёртывание

> Первый production-контур Token создаётся в Timeweb Cloud для старта до 200 пользователей.

## Создано

- VPS `token-prod-1`, Ubuntu 24.04, Москва: 2 vCPU, 4 ГБ RAM, 50 ГБ NVMe;
- вход `root` по выделенному ED25519 SSH-ключу, парольный SSH отключён;
- один провайдерский backup сервера;
- назначены публичные IPv4 `201.24.125.152` и IPv6 `2a03:6f00:a::1:e4b7`;
- создан непривилегированный пользователь `deploy` с доступом по ED25519;
- установлен Docker 29.1.3 и Docker Compose 2.40.3;
- включён UFW: вход разрешён только на TCP 22, 80 и 443;
- зарегистрирован домен `tokenapp.ru`, оплачен до 2027-08-09.
- production-контур описан в `Dockerfile`, `infra/compose/production.yml` и
  `infra/compose/Caddyfile`; наружу публикуются только Caddy 80/443.
- PostgreSQL 16.4 и приложение развёрнуты 2026-08-09; оба контейнера healthy,
  `/health/ready` возвращает `200`, production-база создана и пока пуста;
- Caddy временно остановлен до публичной DNS-делегации, чтобы не расходовать
  лимиты ACME; после появления A-записи он выпускает TLS автоматически.
- пока `tokenapp.ru` возвращает публичный `NXDOMAIN`, Caddy запущен на временном
  HTTPS-адресе `201-24-125-152.sslip.io`; сертификат выпущен, главная страница
  перенаправляет на `/login.html`, `/health/ready` подтверждает доступность БД.
- 2026-08-10 делегация завершена: `tokenapp.ru` резолвится в `201.24.125.152`,
  сертификат основного домена валиден, `https://tokenapp.ru/health/ready` → `200`.
- 2026-08-10 Timeweb разблокировал исходящие 465, 587, 2525 и 25 до
  `smtp.timeweb.ru`; проверено TCP-пробой с самого сервера.
- 2026-08-13 на production выложен коммит `0ef466d` с cockpit-дизайном
  индивидуального занятия 1a без удаления прежних функций. Перед обновлением
  создан дамп PostgreSQL и архив кода в
  `/opt/token/.deploy-backups/20260812-211124`; контейнер приложения пересобран,
  миграция `006_lesson_note_parent_visibility.sql` применена. После выкладки
  app/PostgreSQL/Caddy healthy, `/health/live` и `/health/ready` отвечают `200`,
  email probe — `ok`, публичные JS/CSS содержат runtime 1a.

## Как выкатывается код

`/opt/token` — не git-репозиторий, а синхронизированная копия рабочего дерева,
владелец `deploy`. Обновление: скопировать дерево в `/opt/token`, затем
`docker compose --env-file infra/compose/production.env -f
infra/compose/production.yml up -d --build`. Миграции накатываются самим
приложением на старте (`DATABASE_MIGRATE_ON_START=true`).

Секреты живут только в `infra/compose/production.env` на сервере. Переменные
приложения перечислены в `production.yml`: если обязательная переменная не
проброшена туда, `loadConfig` уронит контейнер на старте, а не деградирует.
`SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD` и `EMAIL_FROM` обязательны —
см. [[ADR-014 Одноразовые токены аккаунта]].

## Целевой состав первого контура

- reverse proxy с TLS;
- один процесс приложения Token;
- PostgreSQL и Redis в изолированной Docker-сети;
- закрытые постоянные volumes;
- приватный S3 для пользовательских файлов и контента ЕГЭ;
- отдельное off-site хранение резервных копий PostgreSQL.

## Блокеры публикации

1. Пароль PostgreSQL раскрыт и не сменён. Меняется не только в `production.env`,
   но и в самой базе (`ALTER USER`): у инициализированного тома пароль хранится
   внутри, и правка переменной одна ничего не даёт.
2. [[Безопасность|Production Identity и безопасность]] ещё не завершена полностью;
   публичный запуск допускается только после минимального security-gate.
