# Сервер

> Один долгоживущий процесс: HTTP + WebSocket + SQLite. Порт 3000, Node.js 20.

## Что делает

1. Подключает сессию к каждому запросу (`Auth.attach`)
2. **Защищает страницы**: любой `*.html` без сессии → `302` на вход
3. Монтирует [[HTTP API]] на `/api`
4. Раздаёт `public/` и `shared/`
5. Поднимает [[Живой канал]] на том же сервере

Создание приложения отделено от запуска: `server/app.js` экспортирует
`createApp()`, а `server/index.js` создаёт HTTP/WebSocket server и слушает порт.
Это позволяет integration-тестам работать без отдельного процесса.

Composition root создаёт application services, in-process event dispatcher и
SQLite repository adapters из [[Модульные границы]]. `server/api.js` отвечает
за HTTP/DTO и не содержит SQL.

Служебные endpoints: `/health/live`, `/health/ready`. Каждый HTTP-ответ получает
`X-Request-Id`, а завершение запроса записывается структурированным JSON-логом.

## Проверки

Node Test Runner + Supertest проверяют HTTP и доменные сценарии, отдельный тест
поднимает настоящий WebSocket upgrade. Playwright проверяет ключевые браузерные
переходы. CI описан в `.github/workflows/ci.yml`.

## Почему один процесс

Нагрузка — десятки одновременных пользователей. Разделять на сервисы
нечего: [[ADR-001 Один процесс вместо микросервисов]]

## Почему не serverless

Нужен долгоживущий процесс для WebSocket. Это тот случай, когда выбор
хостинга диктует функция, а не вкус.

## Запуск

```bash
npm start          # порт 3000
PORT=8080 npm start
TOKEN_DB=/path/to.db npm start
```
