# База данных

> Production — PostgreSQL через `pg`/Kysely. SQLite — development, тесты и временный rollback.

## Production-схема

Схема создаётся версионированными SQL-миграциями `packages/db/migrations`.
Идентификаторы — UUIDv7, время — `timestamptz`, деньги — minor units + currency.
Foreign keys, check/unique constraints и индексы проверяются integration-тестом
и `EXPLAIN`.

JSON-связи прототипа нормализованы в `lesson_tasks`, `assignment_tasks`,
`lesson_links`, `lesson_notes`, `attempt_reviews`, `attempt_history` и
`tutor_subjects`. Для следующих этапов готовы `outbox_events`,
`background_jobs`, `audit_log`.

Соответствие сущностям — [[Домен]].

## Миграция legacy-данных

Справочники, пользователи, связи и учебные данные загружаются идемпотентным ETL.
`legacy_id_map` сохраняет соответствие старых id новым UUID. Проверяются counts,
orphan records, агрегаты и checksum; создаются JSON и Markdown-отчёты.

## Два способа читать

| операция | что отдаёт | кому |
|---|---|---|
| `snapshot(user)` | срез под пользователя | уходит на клиент |
| `fullState()` | всё без фильтров | только внутренняя логика |

Смешивать нельзя: `fullState` содержит эталонные ответы задач.

## Выбор драйвера

`DATABASE_DRIVER=postgres|sqlite`. Production по умолчанию требует PostgreSQL и
`DATABASE_URL`; SQLite не загружается в production-код-путь. Решение:
[[ADR-011 PostgreSQL и Kysely]]. Процедура переноса:
[[Миграция SQLite в PostgreSQL]].

## Optimistic concurrency

[[Invite]], [[Lesson]], [[Assignment]] и [[TaskAttempt]] имеют `version`. Оба
repository adapters выполняют compare-and-swap; конфликт возвращается как HTTP
409 и не затирает более новую запись.
