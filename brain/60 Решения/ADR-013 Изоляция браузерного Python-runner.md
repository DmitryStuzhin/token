# ADR-013 Изоляция браузерного Python-runner

## Контекст

Skulpt компилирует Python в браузере через динамическое создание JavaScript и
поэтому требует `unsafe-eval`. Если разрешить его в CSP основного приложения,
XSS получает существенно более сильный примитив. Одновременно учебный редактор
должен сохранить локальный быстрый запуск кода без влияния на статистику.

## Решение

Основной UI использует строгий CSP без `unsafe-inline` и `unsafe-eval`. Все
скрипты, стили и обработчики вынесены во внешние файлы, style-атрибуты заменены
классами.

Skulpt запускается только в скрытом `iframe sandbox="allow-scripts"` без
`allow-same-origin`. Такой документ получает непрозрачный origin, не читает DOM,
cookies и storage родителя и общается через минимальный `postMessage`-протокол.
Его CSP разрешает скрипты только с точного `PUBLIC_ORIGIN`; `unsafe-eval`
присутствует только в этом sandbox. Для трёх публичных runner-ресурсов CORP
разрешает загрузку из непрозрачного origin. Код и вывод ограничены по размеру,
выполнение — по времени.

## Последствия

- компрометация runner не даёт same-origin-доступ к приложению;
- основной документ сохраняет строгий CSP и запрет inline-атрибутов;
- `PUBLIC_ORIGIN` становится частью политики загрузки runner в production;
- Skulpt остаётся доверенной browser-зависимостью и требует обновления/аудита;
- локальный запуск не меняет попытки, активное время или правильность ответа;
- E2E обязан проверять настоящий запуск Python и отсутствие CSP violations.
