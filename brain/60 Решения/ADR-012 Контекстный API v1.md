# ADR-012 Контекстный API v1

## Контекст

Legacy `/api/state.js` строил весь разрешённый пользователю граф на открытие
каждой страницы. Объём и стоимость росли вместе с историей, DTO не имел
формального контракта, а повтор команд и конкурирующая запись не защищались.

## Решение

Ввести `/api/v1` с OpenAPI 3.1, Problem Details, Zod validation и генерируемым
typed client. Страницы получают минимальный `/screens/:screen`, большие списки —
ресурсные endpoint с opaque cursor. Повторяемые команды используют
`Idempotency-Key`, изменяемые ресурсы — `ETag`/`If-Match`. Тяжёлые чтения
обслуживают восстанавливаемые [[Read-модели API v1]].

Legacy API остаётся временным адаптером под тем же процессом: это позволяет
мигрировать поведение без преждевременного разбиения модульного монолита.

## Последствия

- frontend не загружает полный snapshot, а payload ограничен контекстом экрана;
- OpenAPI одновременно документирует wire contract и создаёт типы;
- появляется хранилище idempotency results и обязанность очищать его по TTL;
- изменение DTO требует обновить контракт, generated client и contract tests;
- после периода наблюдения legacy `/api/state` и `/api/state.js` удаляются.
