# Разделение доступа

> Кто что видит и почему нельзя обойти через браузер.

## Три рубежа

1. **Страницы.** `server/index.js` отдаёт разметку кабинета только
   с сессией. Гость получает `302` до отдачи файла.
2. **Данные.** `snapshot(user)` в `server/db.js` собирает срез: ученик
   получает только своё, репетитор — только своих учеников.
3. **Действия.** Роль и владение проверяет единый policy-слой; routes не
   определяют правила доступа самостоятельно.

## Матрица и object policies

`modules/identity/application/access-policy.js` содержит deny-by-default
матрицу `role × resource × action` и проверки владения объектом. Реализованы
границы lesson/group/invite/enrollment, attempt и tutor→student. Неизвестная
роль, сущность или операция всегда запрещена. Unit-тесты проверяют матрицу, а
HTTP integration — попытки обратиться к объектам другого пользователя.

Успешные чувствительные чтения и предметные изменения централизованно
фиксирует `server/audit.js` в `security_events` с типом `subject_access`.

## Примеры

| Попытка | Ответ |
|---|---|
| ученик создаёт занятие | `403` |
| ученик правит чужую попытку | `403` |
| репетитор трогает чужого ученика | `403` |
| гость запрашивает состояние | срез без личных данных |
