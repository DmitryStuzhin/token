# Token

Платформа подготовки к экзамену с репетитором. Node.js + PostgreSQL + WebSocket,
роли разделены на сервере: ученик и репетитор видят разные кабинеты и разные данные.

## Запуск

```bash
npm install
npm run db:up
npm run db:migrate
npm start
```

Открыть http://localhost:3000 — попадёте на страницу входа.
В development по умолчанию используется SQLite. Production требует PostgreSQL.
Локальный `.env` текущего проекта уже переключает приложение на PostgreSQL в
Docker. `npm run db:down` останавливает контейнер без удаления данных, а
`npm run db:logs` показывает его журнал.

Настройки окружения перечислены в `.env.example`. Приложение само не загружает
`.env`: переменные передаются процессу или через менеджер запуска. Основные:

- `NODE_ENV` — `development`, `test` или `production`;
- `PORT` — HTTP-порт;
- `DATABASE_DRIVER` — `postgres` или `sqlite`;
- `DATABASE_URL` — обязательный PostgreSQL DSN для production;
- `TOKEN_DB` — путь к SQLite-файлу для разработки и rollback;
- `COOKIE_SECURE` — `true` только при работе через HTTPS;
- `LOG_LEVEL` — `debug`, `info`, `warn`, `error` или `silent`.

Проверки состояния: `GET /health/live` и `GET /health/ready`. Readiness отвечает
`503` только при недоступной базе; неработающая почта видна как
`checks.email: "degraded"`, но инстанс остаётся в балансировке.

## Вход по коду

Регистрация и вход подтверждаются кодом из письма вида `K7M-2PQ-9XZ`.
Вход двухфакторный: сначала пароль, затем код. Устройство, прошедшее код,
запоминается на 30 дней, поэтому на своём ноутбуке код спрашивают один раз.
Пять неверных попыток сжигают код — нужно запросить новый. Смена пароля
сбрасывает доверие всех устройств.

## Транзакционная почта

Подтверждение email, коды входа и восстановление пароля уходят через SMTP:
`SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`,
`EMAIL_FROM`. `SMTP_USER` должен совпадать с адресом внутри `EMAIL_FROM` —
провайдеры отклоняют письмо с чужим отправителем. В production переменные
обязательны: без них приложение не стартует. Локально их можно не задавать —
письма тогда только логируются, а коды и ссылки видны в ответе API тестового
окружения.

Диагностика с той машины, где работает приложение:

```bash
npm run mail:check                    # TCP + SMTP AUTH
npm run mail:check -- you@example.com # плюс реальное письмо
```

Скрипт различает три отказа, которые снаружи выглядят одинаково: закрытый
исходящий порт (таймаут TCP — сетевая блокировка, а не приложение), неверные
учётные данные (`EAUTH`) и отказ провайдера принять отправителя (5xx).

## Production Compose

Боевой контур описан в `infra/compose/production.yml`: приложение и PostgreSQL
доступны только во внутренней Docker-сети, наружу опубликованы только Caddy на
80/443. Caddy автоматически выпускает и обновляет бесплатный TLS-сертификат.

```bash
cp infra/compose/production.env.example infra/compose/production.env
# заменить email и оба вхождения пароля PostgreSQL
docker compose --env-file infra/compose/production.env \
  -f infra/compose/production.yml up -d --build
```

`infra/compose/production.env` содержит секреты и игнорируется Git.

## С чего начать

База пустая: ни одного пользователя. Всё появляется после регистрации.

1. Зарегистрируйтесь **репетитором**.
2. В кабинете внизу — **«Приглашения»** → «Новая ссылка» → «Создать». Скопируйте ссылку.
3. Выйдите, зарегистрируйтесь **учеником** с другим email (удобно во втором окне
   браузера или в приватной вкладке — сессии независимы).
4. Откройте ссылку-приглашение → «Присоединиться».
5. Репетитором: **«Назначить занятие»**, затем на странице занятия добавьте
   ссылки (есть заготовки Телемоста, Zoom, Excalidraw, Miro) и прикрепите задания.
6. Учеником: занятие видно, «Подключиться» ведёт на созвон, задачи открываются.
   Пишите код, вводите ответ, жмите «Проверить».
7. Репетитором в другом окне откройте то же занятие — черновик кода ученика
   приходит по WebSocket в реальном времени.

Роль «Родитель» спроектирована, но закрыта: на регистрации помечена как недоступная.

## Архитектура

```
server/
  index.js    HTTP + WebSocket, статика, защита страниц
  api-v1.js   OpenAPI API, экранные DTO, пагинация, ETag и идемпотентность
  db.js       SQLite adapter для разработки и rollback
  auth.js     scrypt, сессии, куки, проверка ролей
  api.js      REST: занятия, задания, приглашения, ответы, проверка
  live.js     комнаты занятий по WebSocket
shared/
  domain.js   предметы с сеткой экзамена, темы, генератор банка задач
  core.js     выборки и агрегаты — один код на сервере и в браузере
public/
  *.html      страницы кабинетов
  assets/     стили, клиент API, оболочка
data/
  token.db    база (создаётся при первом запуске, в git не попадает)
packages/db/
  migrations/ PostgreSQL SQL-миграции и read-модели
  src/         Kysely schema, migrator, ETL и rebuild read-моделей
packages/api-client/
  src/         сгенерированные из OpenAPI типы и typed fetch client
```

**Состояние живёт на сервере.** Каждая страница получает только свой DTO через
`/api/v1/screens/:screen.js`; полный legacy-срез `/api/state.js` клиент больше
не использует. Любое изменение уходит через `Api.*` и проверяется на сервере.

**API имеет контракт.** OpenAPI 3.1 лежит в `docs/openapi.v1.yaml`, ошибки имеют
формат Problem Details, списки поддерживают cursor pagination, фильтры и
сортировку. Команды создания защищены `Idempotency-Key`, конкурентное изменение
занятия — `ETag`/`If-Match`. Типы клиента генерируются командой
`npm run api:generate`.

**Read-модели восстанавливаемы.** PostgreSQL синхронно обновляет проекции
кабинета ученика, дня репетитора, прогресса задания и статистики по предмету.
`npm run db:read-models:rebuild` пересобирает их из первичных фактов и сверяет
результат.

**Права проверяет сервер.** Гость не получит разметку кабинета: `/index.html`
редиректит на вход ещё до отдачи файла. Ученик не создаст занятие, не увидит
чужих работ и не отредактирует чужую попытку — это 401/403, а не спрятанная кнопка.

**Эталонные ответы не покидают сервер.** В публичных screen DTO и `/api/v1/tasks` поля
`answer` нет вовсе; сверка делается в `POST /api/attempts/:id/answer`. Раньше
все ответы лежали в браузере — теперь подсмотреть их нельзя.

**Сессия в httpOnly-куке**, пароль солится и хешируется scrypt. Из JavaScript
куку не прочитать.

## Живое занятие

Комната `lesson:{id}`. Ученик шлёт черновик обычными POST-запросами (heartbeat
раз в 15 секунд и через 600 мс после ввода), сервер рассылает снимок репетитору
по WebSocket. Поток односторонний, поэтому ни CRDT, ни Yjs не нужны.

Подключение авторизуется той же сессионной кукой: в комнату пускают только
репетитора этого занятия и его учеников, посторонним соединение рвётся.

## Банк задач

91 задача, покрыты все номера обоих предметов (информатика — 27 заданий,
профильная математика — 18). Задачи **генерируются**: числа в условии и ответ
считаются из одного зерна, поэтому автопроверка настоящая.

Приёмник импорта на странице «Банк задач» принимает JSON, валидирует на сервере
(предмет, номер в сетке предмета, уникальность id) и кладёт в ту же таблицу.

## Масштабирование

Production-контур уже поддерживает PostgreSQL с пулом соединений,
нормализованными связями, UUIDv7 и optimistic concurrency. Инструкции миграции,
backup, cutover и rollback: [`docs/RUNBOOK POSTGRESQL CUTOVER.md`](docs/RUNBOOK%20POSTGRESQL%20CUTOVER.md).

**Новый предмет — запись в данных, а не правка кода.** Номера заданий, максимумы
баллов и шкала перевода первичного балла в тестовый лежат в `subject.exam`.
Два предмета с разными сетками работают через один код.

**Группа — контейнер, а не владелец статистики.** Занятие и задание адресуются
группе, но попытки и посещаемость пишутся по каждому ученику. Поэтому ученик
может одновременно быть в группе и заниматься индивидуально, и цифры не задвоятся.

## Чего пока нет

Платежи, парсер банка задач, кабинет родителя, редактирование профиля,
восстановление пароля.

Сервер рассчитан на локальный запуск: кука без флага `secure`, HTTPS нет.
Перед публикацией в интернет нужны TLS, `secure: true`, ограничение частоты
попыток входа и расписание резервного копирования PostgreSQL.
