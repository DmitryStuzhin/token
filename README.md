# arcs.studio

Кликабельный прототип кабинета для подготовки к ЕГЭ с репетитором: ученик, репетитор,
родитель и админ в одном приложении.

Демонстрационный интерфейс открывается двойным кликом по `index.html`. Для настоящего
банка заданий добавлены сервер, PostgreSQL и файловое хранилище.
Переключатель роли — внизу бокового меню.

## Главное свойство

Ни одна цифра на экранах не написана в разметке. Всё считается из [`assets/db.js`](assets/db.js)
функциями в [`assets/core.js`](assets/core.js), имена которых совпадают с таблицами доменной
модели: `topicMastery`, `dailyActivity`, `taskNumberStats`, `attendance`, `groupStats`.
Чтобы подключить бэкенд, меняется тело одной функции `DB.load()` — разметка не трогается.

## Что работает по-настоящему

- **Решение задачи** — таймер активного времени (пауза после 2 минут без ввода,
  heartbeat раз в 15 с), черновик кода, автопроверка ответа по правилу задачи
  (`exact`, `ci`, `set`, `numeric` с допуском).
- **Наблюдение за учеником** — откройте `lesson.html` учеником в одной вкладке и
  `lesson.html?role=tutor` в другой: репетитор видит черновик кода с задержкой ~2 с.
  В прототипе через `localStorage`, в бою — WebSocket-комната `lesson:{id}`.
- **Сводка по номерам заданий** — время, процент верных, доля с первой попытки,
  среднее время. Читается как «№17 — 3 ч 10 мин, 77% верных».
- **Группы** — общие занятия и задания, посещаемость и статистика по каждому ученику.
- **Приглашения** — ученик присоединяется к репетитору или группе по ссылке;
  проверяются срок, лимит переходов, вместимость группы и повторное вступление.
- **Импорт заданий** — парсер не написан, но приёмник в админке валидирует JSON
  и кладёт задачи в тот же банк, из которого работают все экраны.

## Масштабирование

**Новый предмет — это запись в данных, а не правка кода.** Номера заданий, максимумы
баллов и шкала перевода первичного балла в тестовый лежат в `subject.exam`. В прототипе
два предмета с разными сетками (информатика — 27 заданий, математика — 18), и обе
работают через один и тот же код. Добавить физику = добавить объект в `subjects`.

**Задача на занятии и задача в д/з — одна сущность** `TaskAttempt` с полем `context`.
Иначе статистика разъехалась бы на два несводимых источника.

**Группа — контейнер, а не владелец статистики.** Занятие и задание адресуются группе,
но попытки и посещаемость пишутся по каждому ученику. Поэтому ученик может одновременно
быть в группе и заниматься индивидуально, и цифры не задвоятся.

## Настоящий банк заданий и импорт КомпЕГЭ

Задания больше не обязаны жить в `assets/db.js`. Серверная часть хранит основную запись
в `tasks`, неизменяемые редакции в `task_versions`, соответствие источнику в
`source_tasks`, историю запусков в `import_runs`, а метаданные вложений — в `assets`.
Сами файлы лежат в `var/storage` с именем на основе SHA-256, поэтому одинаковые файлы
не дублируются. В production этот адаптер можно заменить на S3/R2 без изменения БД.

Запуск:

```bash
cp .env.example .env
docker compose up -d postgres
pnpm install
pnpm migrate
pnpm start
```

После запуска откройте `http://127.0.0.1:8000/admin-import.html`. Можно вводить ID
либо ссылки вида `https://kompege.ru/task?id=23570`. Импорт использует публичный JSON
endpoint отдельного задания, скачивает картинки и дополнительные файлы, очищает HTML,
не создаёт дубли и добавляет новую версию только при изменении содержимого.

Настройки находятся в `.env.example`: ограничение размера файла, задержка между
запросами, адрес БД и каталог хранилища. Один HTTP-запрос принимает максимум 100 ID.

## Что намеренно не сделано

Платежи (кнопки на месте и объясняют, что произойдёт), парсинг банка задач,
формы редактирования профиля, привязок и групп.

Кнопка «сбросить» в правом нижнем углу возвращает демо-данные в исходное состояние.
