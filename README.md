# Token

Платформа подготовки к экзамену с репетитором. Node.js + SQLite + WebSocket,
роли разделены на сервере: ученик и репетитор видят разные кабинеты и разные данные.

## Запуск

```bash
npm install
npm start
```

Открыть http://localhost:3000 — попадёте на страницу входа.
Порт меняется переменной `PORT`, файл базы — `TOKEN_DB`.

## С чего начать

База пустая: ни одного пользователя. Всё появляется после регистрации.

1. Зарегистрируйтесь **репетитором**.
2. В кабинете внизу — **«Приглашения»** → «Новая ссылка» → «Создать». Скопируйте ссылку.
3. Выйдите, зарегистрируйтесь **учеником** с другим email (удобно во втором окне
   браузера или в приватной вкладке — сессии независимы).
4. Откройте ссылку-приглашение → «Присоединиться».
5. Репетитором: **«Назначить занятие»**, затем на странице занятия добавьте
   ссылки (есть заготовки Телемоста, Zoom, Excalidraw, Miro) и прикрепите задания.
6. Учеником: занятие видно, «Подключиться» ведёт на созвон, задачи открываются.
   Пишите код, вводите ответ, жмите «Проверить».
7. Репетитором в другом окне откройте то же занятие — черновик кода ученика
   приходит по WebSocket в реальном времени.

Роль «Родитель» спроектирована, но закрыта: на регистрации помечена как недоступная.

## Архитектура

```
server/
  index.js    HTTP + WebSocket, статика, защита страниц
  db.js       SQLite: схема, справочники, срез данных для пользователя
  auth.js     scrypt, сессии, куки, проверка ролей
  api.js      REST: занятия, задания, приглашения, ответы, проверка
  live.js     комнаты занятий по WebSocket
shared/
  domain.js   предметы с сеткой экзамена, темы, генератор банка задач
  core.js     выборки и агрегаты — один код на сервере и в браузере
public/
  *.html      страницы кабинетов
  assets/     стили, клиент API, оболочка
data/
  token.db    база (создаётся при первом запуске, в git не попадает)
```

**Состояние живёт на сервере.** Браузер получает срез в `/api/state.js` обычным
тегом `<script>` — страница стартует синхронно, без мигания пустым экраном.
Любое изменение уходит через `Api.*` и проверяется на сервере.

**Один код агрегатов.** `shared/core.js` считает статистику и на сервере, и в
браузере — расхождений между экраном и API быть не может.

**Права проверяет сервер.** Гость не получит разметку кабинета: `/index.html`
редиректит на вход ещё до отдачи файла. Ученик не создаст занятие, не увидит
чужих работ и не отредактирует чужую попытку — это 401/403, а не спрятанная кнопка.

**Эталонные ответы не покидают сервер.** В `/api/state` и `/api/tasks` поля
`answer` нет вовсе; сверка делается в `POST /api/attempts/:id/answer`. Раньше
все ответы лежали в браузере — теперь подсмотреть их нельзя.

**Сессия в httpOnly-куке**, пароль солится и хешируется scrypt. Из JavaScript
куку не прочитать.

## Живое занятие

Комната `lesson:{id}`. Ученик шлёт черновик обычными POST-запросами (heartbeat
раз в 15 секунд и через 600 мс после ввода), сервер рассылает снимок репетитору
по WebSocket. Поток односторонний, поэтому ни CRDT, ни Yjs не нужны.

Подключение авторизуется той же сессионной кукой: в комнату пускают только
репетитора этого занятия и его учеников, посторонним соединение рвётся.

## Банк задач

91 задача, покрыты все номера обоих предметов (информатика — 27 заданий,
профильная математика — 18). Задачи **генерируются**: числа в условии и ответ
считаются из одного зерна, поэтому автопроверка настоящая.

Приёмник импорта на странице «Банк задач» принимает JSON, валидирует на сервере
(предмет, номер в сетке предмета, уникальность id) и кладёт в ту же таблицу.

## Масштабирование

**Новый предмет — запись в данных, а не правка кода.** Номера заданий, максимумы
баллов и шкала перевода первичного балла в тестовый лежат в `subject.exam`.
Два предмета с разными сетками работают через один код.

**Группа — контейнер, а не владелец статистики.** Занятие и задание адресуются
группе, но попытки и посещаемость пишутся по каждому ученику. Поэтому ученик
может одновременно быть в группе и заниматься индивидуально, и цифры не задвоятся.

## Чего пока нет

Платежи, парсер банка задач, кабинет родителя, редактирование профиля,
восстановление пароля.

Сервер рассчитан на локальный запуск: кука без флага `secure`, HTTPS нет.
Перед публикацией в интернет нужны TLS, `secure: true`, ограничение частоты
попыток входа и резервное копирование `data/token.db`.
