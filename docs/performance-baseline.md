# Performance baseline прототипа

Дата: 2026-08-08  
Версия Node.js: 20.12.0  
Среда: локальный macOS, один Node.js-процесс, временная SQLite БД

## Набор данных

- 2 предмета;
- 91 задача;
- 0 пользователей;
- 0 занятий.

Это инфраструктурный baseline пустой установки, а не прогноз production.
После появления репрезентативного набора учеников, попыток и занятий должен
быть снят отдельный сценарный baseline.

## Методика

- сервер запускался с `NODE_ENV=test`, отдельным `TOKEN_DB` и `PORT=3137`;
- запросы выполнялись локально через `curl` последовательно;
- p95 — 48-е значение из 50 после сортировки;
- сеть, TLS, конкурентная нагрузка и frontend rendering не измерялись.

## Что ещё требуется для полного T0-006

Добавлен воспроизводимый сценарий `npm run baseline`. Он создаёт временную БД,
наполняет её данными, выполняет 30 измерений каждого среза и удаляет БД.

### Репрезентативный набор стартового масштаба

- 200 пользователей: 20 репетиторов и 180 учеников;
- 20 групп;
- 360 занятий;
- 180 домашних заданий;
- 3 600 проверенных попыток.

### Результаты срезов

| Срез | Average | p95 | Max | Payload | SQL statements |
|---|---:|---:|---:|---:|---:|
| Гость | 0,417 мс | 0,579 мс | 0,795 мс | 44 681 B | 3 |
| Ученик | 0,885 мс | 1,315 мс | 1,483 мс | 57 012 B | 20 |
| Репетитор, 9 учеников | 2,605 мс | 2,994 мс | 3,154 мс | 140 756 B | 23 |

RSS после генерации и измерений: 53,5 MiB; используемый heap: 6,7 MiB.

Скорость на пустой/синтетической локальной БД достаточна для первых 200
пользователей. Главный ранний риск — не CPU, а линейный рост payload полного
snapshot и выдача всех попыток репетитору. Эти значения становятся контрольной
точкой для этапов PostgreSQL и API v1.
