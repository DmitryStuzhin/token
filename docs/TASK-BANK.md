# Банк заданий

## Границы хранения

- PostgreSQL хранит сущности, связи, версии, журнал импорта и метаданные файлов.
- `var/storage` хранит бинарные данные. Ключ строится из SHA-256; повторная загрузка
  одного файла не создаёт вторую копию.
- `source_tasks` обеспечивает идемпотентность по паре `(source, external_id)`.
- `task_versions` неизменяемы. `tasks.current_version_id` указывает на актуальную версию.

## Жизненный цикл импорта

1. Пользователь отправляет до 100 ID или URL.
2. Создаётся `import_runs` со статусом `running`.
3. Для каждого ID загружается публичное представление задания.
4. HTML очищается; относительные URL приводятся к абсолютным.
5. Картинки из HTML и `files[]` скачиваются с лимитом размера.
6. По нормализованным данным вычисляется `content_hash`.
7. Новая задача создаётся; совпадающая остаётся без изменений; изменившаяся получает
   следующую версию. Ошибка одного задания не откатывает успешно импортированные.
8. Запуск завершается как `completed`, `partial` или `failed`.

## Переход на объектное хранилище

Контракт `storeBuffer(bytes, filename)` отделён в `server/storage.js`. Для S3/R2 нужно
заменить запись на диск на `PutObject`, сохранив возвращаемые `sha256`, `storageKey` и
`sizeBytes`. Таблицы и импортёр менять не потребуется.

## Безопасность перед публикацией

Административный API сейчас рассчитан на локальную разработку. Перед размещением в
интернете необходимо добавить аутентификацию администратора, CSRF-защиту, сетевой
rate limit и фоновую очередь. Импортировать материалы следует только при наличии права
на их использование и с соблюдением условий источника.
